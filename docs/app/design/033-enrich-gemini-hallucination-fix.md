# 033: enrich-gemini.js ハルシネーション対策

**Issue**: #42
**作成日**: 2026-03-28
**ステータス**: レビュー待ち

---

## 概要

`scripts/enrich-gemini.js` による書誌情報充足の実行後、誤ったデータが `books.json` に混入することが判明した。
Gemini が書籍を特定できない場合でも推測値を返すハルシネーションが原因。

**例**:
- 書籍「納品をなくせばうまくいく」（ASIN: B00LSQ8G4W）
  - 正：著者「倉貫義人」、ページ数 240
  - Gemini の回答：著者「飯田 岳志」、ページ数 192（類似書籍の情報と推測）

2点の変更でハルシネーションを抑制する：
1. プロンプトの推測禁止指示を強化する
2. モデルを `gemini-2.5-flash-lite` → `gemini-2.5-flash` に変更する

---

## 技術的アプローチ

### 1. プロンプトの推測禁止指示強化

#### 現状

```
（不明な場合は null）
```

「不明」の定義が曖昧で、Gemini が「ある程度確信できる推測」を「不明でない」と判断して回答できてしまう。

#### 変更後

```
この書籍の著者名とページ数を確実に知っている場合のみ回答してください。
情報が不確か・類似タイトルしか見当たらない・複数候補がある場合は、必ずnullを返してください。
推測や類似書籍の情報を使用しないでください。
```

`buildPrompt()` 内のプロンプト文字列（`enrich-gemini.js` の32〜34行目付近）を上記に置き換える。

### 2. モデル変更

| 項目 | 変更前 | 変更後 |
|-----|-------|-------|
| `MODEL_NAME` | `gemini-2.5-flash-lite` | `gemini-2.5-flash` |

`gemini-2.5-flash-lite` は軽量モデルのためプロンプト指示の遵守能力が低い。
`gemini-2.5-flash` は同系列の上位モデルであり、事実精度が向上しハルシネーション率が低下する。
無料枠の消費量は増加するが、誤データ混入リスクの低減効果が大きい。

`MODEL_NAME` 定数（`enrich-gemini.js` の10行目）を変更する。
なお、enrichment データには `model` フィールドが記録されるため、変更後の実行結果は `gemini-2.5-flash` として保存される。

## 影響範囲

| カテゴリ | 対象 | 変更内容 |
|---------|-----|---------|
| 変更スクリプト | `scripts/enrich-gemini.js` | `MODEL_NAME` 定数の変更、`buildPrompt()` 内プロンプト文字列の変更 |
| データファイル | `data/book-gemini-enrichment.json` | 変更なし（既存データを保持。再実行時は差分モードで上書き対象外） |
| テスト | `scripts/enrich-gemini.test.js` | `buildPrompt` テストの期待値を新プロンプトに合わせて更新が必要な可能性あり |
| `process.js` | 変更なし | — |
| `CLAUDE.md` | `MODEL_NAME` の記載なし | 変更不要 |

## テスト計画

| ID | テスト項目 | 確認内容 |
|----|-----------|---------|
| T-1 | プロンプト内容 | 新プロンプトに推測禁止の明示的な指示が含まれること（`buildPrompt` テスト更新） |
| T-2 | 既存テストの継続パス | `buildPrompt`・`parseResponse` の既存テストがすべてパスすること |
| T-3 | モデル定数 | `MODEL_NAME` が `gemini-2.5-flash` に変更されていること（コードレビューで確認） |

既存の `parseResponse` テストはロジック変更がないためそのままパスする想定。
`buildPrompt` テストは「`JSONのみを出力`」の文言が含まれること等を検証しており、新プロンプトにも同文言が残る場合は変更不要。ただし削除する場合はテストを更新する。

---

## 注意事項

- 既存の `book-gemini-enrichment.json` に記録された誤データは、本 Issue の範囲外。
  誤データの修正は手動補正（`book-corrections.json`）または別 Issue で対応する。
- 本変更後に `--all` オプションで再実行すると、既登録データを上書きしてより正確なデータを取得できる。
  ただし API クォータ消費に注意が必要。
